# Коттеджный посёлок «Солнечный Луг» — лендинг

Одностраничный сайт по контенту из [solnechny-lug-site_1.md](../solnechny-lug-site_1.md).
React + TypeScript + Tailwind на Vite. Тёмная схема, видео на первом экране, стеклянные панели.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # проверка типов + сборка в dist/
npm run preview  # посмотреть собранную версию
```

## Что проверить до запуска

Обязательное — без этого публиковать нельзя:

1. **Правовой статус дома.** На кадастровой схеме ([shema-uchastka.png](public/photos/shema-uchastka.png))
   объект помечен как «здание блокированной застройки — отдельно стоящие дома с общей
   стеной», и на фото дома действительно стоят сблокированными рядами. В тексте же везде
   значится ИЖС. Это разные категории, и для покупателя разница принципиальна (ипотека,
   прописка, права на землю). Свериться с выпиской ЕГРН и привести сайт в соответствие.
2. **Контакты** — в [src/content.ts](src/content.ts) стоят заглушки `+7 (000) 000-00-00`
   и `info@solnechny-lug.ru`.
3. **Активируйте приём заявок на почту** — см. следующий раздел. Без этого шага первая
   заявка не дойдёт.

Из пометок «уточнить» в исходном документе:

| Что | Сейчас на сайте |
| --- | --- |
| Состояние дома | «Под чистовую отделку» |
| Коммуникации | «Газ, вода, канализация в доме» |
| Лыжная трасса | 400 метров |
| Площадь / участок | ~120 м², 4–4,5 сотки |
| Ипотека | Ответ в FAQ обтекаемый — заменить на конкретные банки и программы |
| Собственность и документы | Ответ в FAQ обтекаемый — заменить на точную формулировку |

Отдельно: **«около 3 км до Волги, 25 минут пешком»** — это темп 7 км/ч, быстрее обычного
шага. Либо расстояние меньше, либо времени нужно больше; сейчас на сайте стоит вариант
из документа без изменений.

## Сайт опубликован

**https://anastasiaek.github.io/solnechny-lug/**

Репозиторий: `AnastasiaEk/solnechny-lug`. Workflow
[.github/workflows/deploy.yml](.github/workflows/deploy.yml) пересобирает и выкладывает
сайт при каждом пуше в `main` — вручную ничего запускать не нужно:

```bash
git add -A && git commit -m "правки текста" && git push
```

Сайт лежит в подпапке `/solnechny-lug/`, поэтому `base` в
[vite.config.ts](vite.config.ts) берётся из переменной `VITE_BASE`, а ссылки на файлы из
`public/` идут через [asset()](src/lib/asset.ts). Без этого картинки и видео отдавали бы 404.

### Свой домен

Когда появится доступ к DNS нужного домена:

1. Создать `public/CNAME` с одной строкой — именем домена.
2. Прописать домен в `index.html` (canonical, og:url, og:image, JSON-LD) и
   `public/sitemap.xml`; в `public/robots.txt` — в директиве `Sitemap` и вернуть `Host`.
3. В [.github/workflows/deploy.yml](.github/workflows/deploy.yml) убрать `VITE_BASE` —
   на своём домене сайт живёт в корне.
4. В DNS домена добавить `CNAME  <поддомен>  →  anastasiaek.github.io.`
5. В репозитории **Settings → Pages → Custom domain** вписать домен и включить
   **Enforce HTTPS**. Сертификат GitHub выпустит сам за 10–20 минут.

Пока домена нет, canonical и sitemap указывают на адрес github.io — иначе поисковики
считали бы канонической несуществующую страницу и не проиндексировали сайт вовсе.

Альтернатива GitHub: любой российский хостинг — Timeweb, Beget, Reg.ru (150–300 ₽/мес),
заливается папка `dist/` целиком.

После публикации, в таком порядке:

1. Добавить сайт в **Яндекс.Вебмастер** и **Google Search Console**, подтвердить права,
   отправить `sitemap.xml`.
2. Завести карточку в **Яндекс Бизнесе** — для локальных запросов она даёт больше, чем
   органика молодого сайта.
3. Разместить объект на **Авито, Домклик, Циан**. По запросам вроде «купить дом» выдачу
   держат агрегаторы; отдельный сайт на одном объекте с ними не конкурирует.

## Что уже сделано для поиска

- `title` и `description` под геозапросы: «купить дом в Волгореченске», «ИЖС», «Костромская
  область».
- Разметка Schema.org (`RealEstateAgent` + `SingleFamilyResidence` с ценой, площадью,
  координатами) — её читают и Яндекс, и Google.
- `robots.txt` с директивой `Host` и `sitemap.xml`.
- Канонический адрес, Open Graph и отдельная картинка превью `og-image.jpg` 1200×630.
- Вес страницы: фото переведены в WebP (4,0 МБ → 0,5 МБ), фоновое видео пережато без
  звуковой дорожки (4,2 МБ → 1,0 МБ). Скорость загрузки учитывается при ранжировании.

Чего технически сделать нельзя: молодой сайт на один объект не выйдет в топ по
высокочастотным запросам вроде «купить дом» или «недвижимость» — там агрегаторы с
многолетней историей. Достижимая цель — низкочастотные геозапросы: «дом в Волгореченске
у леса», «ЖК Солнечный Луг», «дом ИЖС Волгореченск». Срок — 3–6 месяцев после индексации.

## Куда приходят заявки

Настройка — объект `leadDelivery` в [src/content.ts](src/content.ts), отправка —
[src/lib/submitLead.ts](src/lib/submitLead.ts). Три режима.

### `mode: 'google-form'` — запись в Google-форму (включён сейчас)

Заявки падают в форму «Новая форма» с тремя вопросами: «Имя», «телефон», «удобное время».
Адрес и номера полей уже прописаны в `leadDelivery.googleForm`, отправка проверена — тестовая
запись прошла.

Если поменяете вопросы в форме, номера полей изменятся. Взять новые: «⋮» → «Получить
предзаполненную ссылку», вписать в поля слова-маркеры, скопировать ссылку — номера будут
прямо в её адресе. В `actionUrl` хвост `/viewform?...` заменяется на `/formResponse`.

Настройки формы, без которых заявки от посетителей не пройдут: «Собирать адреса
электронной почты» — выключено, «Ограничить до 1 ответа» — выключено. Иначе Google
потребует вход в аккаунт.

Google не отдаёт CORS-заголовки, поэтому браузер не может прочитать ответ: сайт покажет
«Заявка отправлена», даже если Google её отклонит. После правок в форме обязательно
проверяйте, что тестовая запись дошла до вкладки «Ответы».

### `mode: 'email'` — письмо на почту

Запасной вариант: заявки уходят на `eka-energo@mail.ru` через сервис FormSubmit.
Регистрация не нужна, но **нужна разовая активация**:

1. Откройте сайт и отправьте тестовую заявку через форму.
2. На `eka-energo@mail.ru` придёт письмо «Confirm your email» от FormSubmit.
3. Нажмите в нём кнопку подтверждения.

После этого заявки приходят письмом сразу: имя, телефон, удобное время. Первая тестовая
заявка до почты не дойдёт — она и запускает активацию.

Адрес почты виден в исходном коде страницы. Он и так опубликован в футере, так что
ничего нового это не раскрывает; если нужно спрятать — на formsubmit.co есть режим со
скрытым хешем вместо адреса, его выдают после активации.

### `mode: 'custom'` — свой бэкенд или вебхук CRM

POST с JSON `{ name, phone, time }` на адрес из `customEndpoint`. Успехом считается
любой ответ со статусом 2xx.

## Карта

Встроен виджет Яндекс.Карт: спутниковый слой, метка на Луговой улице
(`41.177802, 57.435402`), зум 18. Адрес виджета — константа `mapEmbedSrc` в
[src/content.ts](src/content.ts), рядом лежит `contacts.mapUrl` для кнопки «Открыть
в Яндекс.Картах». Чтобы сместить метку или сменить слой, замените обе ссылки на новые
из конструктора карт.

## Материалы

Фото и планировки лежат в [public/photos/](public/photos/) — это исходные `IMG_*.PNG` с
рабочего стола, переименованные по смыслу. Планы этажей дали точные площади комнат,
они выведены списком рядом со схемами. Видео первого экрана — `public/background.mp4`.

Изображения отдаются в PNG как есть (~2,5 МБ на всю галерею). Перед публикацией их стоит
сжать в WebP — это самая большая часть веса страницы.

## Решения по оформлению

- **Природная палитра.** Основа — «кора» `#0A0F0B`, поверх неё три мягких радиальных
  пятна: мох, тёплый песок и хвоя (задаются в [src/index.css](src/index.css) на `body`,
  `background-attachment: fixed`, чтобы фон не ехал за длинной страницей). Акцент —
  `moss` `#A8C49B` на надзаголовках и иконках; оттенки объявлены в
  [tailwind.config.js](tailwind.config.js) как `bark` / `moss` / `sand` / `fern`.
- **Силуэты пейзажа** — [LandscapeBackdrop.tsx](src/components/LandscapeBackdrop.tsx).
  Три слоя кромки леса (дальний горизонт, перелесок, ближние деревья) плюс травинки по
  нижнему краю и мягкий просвет неба у горизонта. Пути не нарисованы вручную, а
  собираются функцией `treelinePath` из чередующихся округлых и остроконечных крон;
  генератор случайных чисел с фиксированным зерном, поэтому силуэт одинаков при каждой
  загрузке. Слой закреплён у нижнего края экрана, отсюда `relative z-10` на `main` и
  футере: позиционированные элементы рисуются позже обычного потока, без этого фон
  накрыл бы контент.
- **Листья за курсором** — [LeafCursor.tsx](src/components/LeafCursor.tsx). Листик
  рождается не чаще, чем раз в 90 px пути курсора, одновременно живёт максимум 18 штук,
  каждый сносит вбок, кружит и тает за ~2,5 с. Слой `pointer-events: none`, поэтому по
  ссылкам под ним по-прежнему можно кликать. На тач-экранах (`pointer: coarse`) и при
  системной настройке «уменьшить движение» эффект не включается вовсе.
- **Шрифт — Inter.** Скилл ui-ux-pro-max предлагал пару Cinzel + Josefin Sans, но ни в
  одном из них нет кириллицы, для русского текста они не годятся.
- **Иконки — lucide-react**, не эмодзи: одинаковая толщина обводки, наследуют цвет темы.
- **Анимации** отключаются при системной настройке «уменьшить движение».
- **`.liquid-glass`** оставлен только для навигации и карточек поверх видео. Ниже первого
  экрана используется более лёгкий `.panel` — блюр там нечего размывать, а текст он мылит.
